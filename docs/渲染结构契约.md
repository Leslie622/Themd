# 渲染结构契约——金样语料与规范记录

> 状态:**生效**。上游决策见 [渲染统一方案.md](渲染统一方案.md)(§3:单一真相 = 一个函数
> C(笔记)→ 规范 HTML;本文定义这个「规范 HTML」到底是什么)。
> 执行机构:`src/modules/rendering/golden/`——`corpus.md`(全元素语料)+
> `corpus.expected.html`(冻结期望,即规范本体)+ `golden-corpus.test.ts`(守门)。

---

## 1. 契约的地位与使用方式

- 任何渲染器对同一语料的输出必须与 `corpus.expected.html` **逐字节一致**
  (比较前统一 LF 归一 + 去首尾空白,见测试文件)。
- 三类读者:
  - **静态消费方**(预览/工厂/导出):换引擎时以字符串相等为验收;
  - **TipTap schema 作者**:toDOM 逐节点对齐本文 §3 的结构;
  - **CSS 作者**(theme-base.css):选择器只准依赖本文 §3 定义的结构(§4 规约)。
- **变更纪律:先改本文,再重冻结。**重新冻结命令:
  - Git Bash:`GOLDEN_UPDATE=1 npx vitest run src/modules/rendering/golden`
  - PowerShell:`$env:GOLDEN_UPDATE=1; npx vitest run src/modules/rendering/golden`
- 语料覆盖矩阵:标题六级(+Setext 两级+中英混排 slug)/段落/行内五件套/链接
  (含 title+query 转义)/自动链接(裸 URL+尖括号)/图片(alt/title/data URI/空 alt)/
  紧凑与宽松列表/嵌套列表(无序+有序)/有序 start/任务列表(勾与未勾)/引用+嵌套引用/
  GFM 提示块五类+同段正文+未知类型降级/行内代码/代码块(hljs+无语言)/mermaid 占位/
  行内与块级数学/表格三向对齐/分隔线/软换行 br/硬换行(反斜杠)/typographer 标点/
  转义与实体/块级·行内·注释三态内嵌 HTML/链接引用(脚注语法边界)。

## 2. 解析策略(输入端,契约的一半)

| 策略 | 值 | 说明 |
|---|---|---|
| `html` | true | 内嵌 HTML 透传。解析保真政策已拍板(方案 §6.2 选①):TipTap 侧建 raw HTML 节点对齐,不丢内容 |
| `breaks` | true | 软换行渲染 `<br>`(Typora/Obsidian 同款;与 GitHub 网页版折叠行为不同——产品决策已定) |
| `typographer` | true | 智能标点:直引号→弯引号、`--`→–、`---`→—、`(c)`→©。导出文本与源码字面不同,已知且有意 |
| `linkify` | true | 裸 URL 自动成链 |
| 脚注 | 无插件 | `[^1]` 按 CommonMark 链接引用解析(行内成引用链接、定义行被消费),**不是字面渲染**——已冻结为已知边界,引入脚注插件=契约变更 |

## 3. 逐元素规范结构(输出端)

「来源」= 标准(CommonMark/GFM 或其生态惯例,可移植 CSS 可依赖)/
本家(Themd 自定义,可移植 CSS 同样可依赖——类名是本家命名空间)。

| 元素 | 规范结构 | 来源 |
|---|---|---|
| 标题 | `<h1 id="…">`…`</h1>`;id = slug(见下) | 本家(锚点) |
| slug 规则 | `trim → 小写 → 空白折叠为 - → 去除非 [\w 中文 -] 字符`;中文字符保留(`## 二级标题` → `id="二级标题"`) | 本家 |
| 行内强调 | `<em>`/`<strong>`/`<s>`(~~删除线~~ → `<s>`,非 `<del>`) | 标准 |
| 行内代码 | `<code>` | 标准 |
| 链接 | `<a href title>`;`&` 转义为 `&amp;` | 标准 |
| 图片 | `<img src alt title loading="lazy" decoding="async">`(属性顺序固定);**src 改写(asset://、相对路径)是渲染期环境行为,不属于结构**——语料用远程/data URI 冻结纯结构,TipTap 侧接同一 `resolveImageSrcSync` | 标准+本家(懒加载属性) |
| 紧凑列表 | `<ul>/<ol>` + `<li>文本</li>`(无 p 包装) | 标准 |
| 宽松列表 | `<li>` 换行包 `<p>`——与紧凑**两形态并存是规范的一部分**(空行分隔项即宽松);同类型列表间空行不断列表(要断开须隔段落) | 标准 |
| 有序 start | `<ol start="5">` | 标准 |
| 任务列表 | `<ul class="contains-task-list">` + `<li class="task-list-item"><input class="task-list-item-checkbox" checked="" disabled="" type="checkbox"> 文本</li>`(紧凑形态,input 是 li 直接子) | 本家(插件形态,GitHub 兼容)。**迁移铁律:TipTap taskItem 的 toDOM 必须对齐此形态——禁 div 包装、禁 data-type 私有属性** |
| 引用 | 标准 `<blockquote>`,可嵌套 | 标准 |
| GFM 提示块 | `<div class="themd-callout themd-callout-{type}" data-alert="{type}">`(blockquote 变身 div);首段标题 `<p class="themd-callout-title"><svg class="themd-callout-icon" …>Octicon</svg>{Label}</p>`;标记与正文同段时标题前插;未知类型降级普通引用 | 本家 |
| 代码块 | `<pre><code class="language-{lang}">hljs 输出</code></pre>`;未注册语言纯转义无 class | 标准+hljs 生态 |
| mermaid | `<div class="themd-mermaid" data-src="{encodeURIComponent(源码)}">{转义源码}</div>` 占位;SVG 注入是挂载后/导出预热的后处理,**结构契约以占位形态为准** | 本家 |
| 数学 | KaTeX 标准输出:行内 `<span class="katex">`,块级包 `<span class="katex-display">` | KaTeX 生态 |
| 表格 | GFM `<table>`;对齐落 `<th style="text-align:left|center|right">`(td 同步)——**对齐信息在 style 属性,TipTap 侧必须保留** | 标准 |
| 分隔线 | `<hr>` | 标准 |
| 换行 | 软换行/硬换行(行尾反斜杠)均 `<br>` | 本家(breaks:true) |
| 内嵌 HTML | 块级/行内/注释三态原样透传 | 标准(html:true) |
| 链接引用 | `[^1]` → `<a href="{percent-encoded 定义}">`;定义行被消费不出现 | 标准(见 §2 脚注边界) |

## 4. CSS 规约(theme-base.css 的约束,方案 I2 的落地)

1. 选择器只准依赖 §3 定义的结构与类名;**禁** `.live-editor-shell` 前缀、
   **禁** `data-type` 私有属性钩子、**禁** 依赖引擎包装元素(如 `li > div >`)。
2. **紧凑/宽松两形态必须观感一致**:项级间距落 `li`(或 `li` 与 `li > p` 并列双写),
   不得只写 `li > p`——GitHub/Typora 的紧凑列表里没有 p。
3. `themd-callout`/`themd-mermaid`/`task-list-item` 等本家类名可依赖,
   属可移植 CSS 包的公开面。
4. 任务列表完成态选择器须同时覆盖「标准形态」(`li:has(> input:checked)`)
   与迁移期 TipTap 形态,迁移完成后收敛为仅标准形态。

## 5. 已知边界(修订须走「先改文档再重冻结」)

- **脚注**:无插件,行为见 §2;引入插件即契约变更。
- **hljs 语言集**:仅 markdown-renderer.ts 注册的语言有高亮;新增注册语言会改
  冻结输出 → 属契约变更。
- **KaTeX/hljs 版本升级**可能改变输出字节:升级须重冻结并对 diff 逐行审查,
  不许盲刷。
- **typographer/linkify 的文本改写**:导出 HTML 文本与源码字面存在实体级差异,
  有意保留。
- **环境相关的 src 改写**(asset://)不冻结在语料里;其行为由
  `resolveImageSrcSync` 单测与渲染期链路保障。

## 6. 迁移验收(TipTap 侧如何消费本契约)

- **输出线**:`generateHTML(parse(corpus.md))` 与 `corpus.expected.html`
  归一化后逐字节相等。
- **输入线**:解析保真政策①——schema 不认识的块级/行内 HTML 走 raw HTML 节点,
  序列化回 Markdown 字节保真(live-editor 既有字节保真协议承接)。
- **差异处理方向**:TipTap 侧对齐本契约;若发现 md-it 侧实际行为与本文表述不符,
  先修订本文并重冻结,**不许静默改期望**。
