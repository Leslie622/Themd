# 主题系统设计（v1 草案）

> 一句话：把「渲染样式」做成一等公民——内置默认主题，可视化逐元素定制，主题可创建、可导入、可导出。
> 状态：**设计稿，待评审**。定稿后按第 9 节路线图分期实现。

---

## 0. 先回答两个前置问题

### 0.1 「默认样式」有官方规定吗？

**没有。** Markdown 的规范（CommonMark、GFM）只规定「语法 → HTML 标签」的映射，比如 `**x**` → `<strong>x</strong>`，至于 strong 长什么样，规范不管。

行业里的事实标准默认样式有三个来源：

| 来源 | 说明 |
|---|---|
| GitHub 渲染样式 | `github-markdown-css`，最常见的「MD 该有的样子」 |
| Typora 默认主题 | 本质就是一份改自 GitHub 的 CSS（`github.css`） |
| Tailwind Typography（`prose`） | 本项目**现在用的**就是它 |

结论：默认样式由我们自己定义。内置两套：**极简**（默认，基础样式表的回落值集合，全站最简洁的基准观感）和 **GitHub**（复刻 GitHub 网页版渲染）；用户打开应用即见极简，想换风格一键切换或进主题工场。

### 0.2 现在的技术栈能实现可视化逐元素自定义吗？

**完全能，而且条件特别好**，三个理由：

1. **HTML 输出完全可控**：markdown-it 的 `renderer.rules` 让我们掌握每种元素的最终 HTML 结构和类名，选择器有保障，不存在「第三方渲染器输出变了样式就崩」的问题。
2. **CSS 变量是纯浏览器能力**：样式引擎用「容器作用域 + CSS 自定义属性」实现（见第 5 节），改一个属性 = 改一个 CSS 变量，毫秒级生效，不需要任何 CSS 处理库。
3. **配套能力都在**：存储有 zustand persist 先例（新建独立 key，不动 `md-notebook`）；解析用户导入的 CSS 有浏览器原生 `CSSStyleSheet` API；后期自定义 CSS 编辑器可直接复用已注册的 CodeMirror css 语言。

**不需要新增任何重量级依赖。**

## 1. 产品定位

参照对象与差异化：

| 产品 | 它的做法 | Themd 学什么 / 不学什么 |
|---|---|---|
| Typora | 导入 CSS 主题文件，整套切换 | 学「导入主题文件」；补上它没有的可视化定制 |
| Obsidian | CSS snippet + 主题市场，纯手写 CSS | 学「主题可分享」；把门槛从「会写 CSS」降到「会点鼠标」 |
| 语雀/Notion 导出 | 固定几套模板 | 不学——我们要的是完全开放的自定义 |

**核心卖点一句话：像 Typora 一样能导入主题，但不用写一行 CSS 就能把加粗、标题、表格……每一项改成自己想要的样子；改完还能导出分享。**

## 2. 核心概念模型

```
主题（Theme）= 一份「差异化的样式令牌（tokens）」+ 可选的附加 CSS
默认主题     = 内置的一套完整观感（迁移自现在的 prose）
```

三条铁律：

1. **主题只存差异**。用户在「默认」基础上只改了加粗颜色，这份主题里就只有 `strong.color` 一条令牌。没设置的属性自动回落默认值——这样「恢复某元素默认」= 删掉对应令牌，天然实现。
2. **令牌 → CSS 变量 → 基础样式消费**。运行时把令牌编译成 CSS 变量挂在预览容器上，静态的基础样式表用 `var(--t-xxx, 默认值)` 逐项消费。
3. **作用域限定在正文容器**（`.themd-prose`）。所有主题样式只影响预览区正文，永不污染应用界面（侧栏、编辑器、弹窗）。

内置主题固定两套，直接写死在代码里（不占用户存储、不可删除、随版本更新）：

| id | 名称 | 形态 |
|---|---|---|
| `default` | 极简 | `tokens` 为空——基础样式表的回落值就是它，全站「最简洁」的基准观感 |
| `github` | GitHub | 一份令牌差异集，复刻 GitHub 网页版渲染（亮色） |

数据流全景：

```
主题工场 UI 改一个属性
  → theme store 更新令牌（zustand persist → localStorage: themd-themes）
  → compile.ts 把令牌编译成 { '--t-strong-color': '#c0392b', ... }
  → PreviewPane 容器 style 挂上这些变量
  → theme-base.css 中 .themd-prose strong { color: var(--t-strong-color, inherit) }
  → 立即生效，无需重新生成任何 CSS 文本
```

导出是同一条链路的反向：令牌 + 默认值 → 解析成完整值 → 编译成独立 `.css` 文本 / `.themd.json` 主题包。

## 3. 可定制元素清单（覆盖矩阵）

这是产品的核心规格：**Markdown 里出现的每一种东西，都能在这里找到对应设置项。**

### 全局与基础

| 元素 | 典型可调项 |
|---|---|
| 正文根（全篇） | 字体、字号、行高、字色、字间距、正文最大宽度 |
| 段落 p | 段间距、对齐方式、首行缩进 |

### 标题（共用 + h1–h6 逐级）

| 范围 | 典型可调项 |
|---|---|
| 全部标题 | 字体、颜色 |
| 每一级 h1…h6 | 字号、字重、颜色、对齐、段前/段后间距 |
| h1 / h2 附加 | 下边框开关 + 边框颜色（GitHub 风格必备） |

### 行内元素

| 元素 | 典型可调项 |
|---|---|
| 加粗 strong | 颜色、字重、字号、背景色（做出「高亮笔」效果） |
| 斜体 em | 颜色、是否倾斜 |
| 删除线 del | 文字颜色、删除线颜色 |
| 行内代码 | 字体、字号、颜色、背景、边框、圆角、内边距 |
| 链接 a | 颜色、下划线策略（始终/悬停/无）、悬停色 |

### 列表

| 元素 | 典型可调项 |
|---|---|
| 无序列表 ul | 缩进、项间距、圆点颜色 |
| 有序列表 ol | 编号颜色、编号字重 |
| 任务列表 | 勾选框主色、已完成文字置灰/加删除线开关 |

### 块级元素

| 元素 | 典型可调项 |
|---|---|
| 引用 blockquote | 左边框宽/色、背景色、文字色、圆角、内边距、是否斜体 |
| 代码块 pre>code | 背景、圆角、边框、内边距、字体、字号、行高、**高亮配色方案**（内置几套 hljs 主题下拉选择） |
| 表格 | 边框颜色/线宽、表头背景/字重、斑马纹开关、单元格内边距、整体圆角 |
| 分割线 hr | 线色、线型、粗细（或换成居中装饰符样式） |
| 图片 img | 圆角、阴影开关、最大宽度、居中、边框 |

> 未来元素（KaTeX、mermaid、脚注、目录）接入 markdown-it 后，在这里各加一行即可——扩展机制见 6.4。

## 4. 数据模型

```ts
// 令牌键名约定：'<元素>.<属性>'（camelCase），运行时映射为 CSS 变量 --t-<元素>-<kebab 属性>
// 值统一为字符串（如 '700'、'1.5em'、'#0969da'），控件类型由元数据约束（见 6.4）
type TokenValue = string

interface ThemeFile {
  version: 1
  id: string              // uuid；内置主题用固定 id
  name: string
  builtin?: boolean       // 内置预设不可删除，可复制后修改
  tokens: Record<string, TokenValue>   // 稀疏：只存与默认不同的项
  extraCss?: string       // P4：附加自定义 CSS
}
```

存储：新建 `store-themes.ts`（zustand + persist，key `themd-themes`），记录主题列表 + 当前激活主题 id。**不动现有 `md-notebook` key**（项目地图明令禁止，改了丢用户数据）。

```ts
interface ThemeState {
  themes: ThemeFile[]
  activeId: string            // 'default' 为内置默认主题
  upsert / remove / duplicate / rename / importTheme / exportTheme ...
}
```

## 5. 样式引擎

### 5.1 弃用 prose，自建基础样式表

预览区从 Tailwind Typography（`prose` 类）切换到自建的 `theme-base.css` + `.themd-prose` 类。原因：prose 的默认值会和我们注入的变量打架，定制越深越别扭；而 markdown-it 输出的就是干净的 `<h1><p><strong>` 标准结构，为这十几个元素手写基础样式工作量可控，换来的是 100% 控制权。

> Tailwind Typography 插件保留（`@plugin` 不删），只是预览正文不再用它。应用界面其他部分照旧。

### 5.2 基础样式长什么样（示例）

```css
.themd-prose {
  font-family: var(--t-root-font, 'Geist Variable', sans-serif);
  font-size:   var(--t-root-size, 16px);
  line-height: var(--t-root-leading, 1.75);
  color:       var(--t-root-color, var(--foreground));
  max-width:   var(--t-root-width, 48rem);
}
.themd-prose strong {
  color: var(--t-strong-color);           /* 变量未注入 → 回落继承，即默认观感 */
  font-weight: var(--t-strong-weight, 700);
  background: var(--t-strong-bg);
}
```

要点：**没设置的令牌根本不出现在容器 style 里**，`var()` 回落直接生效；「恢复默认」= 删令牌，不需要算「默认值是多少」。

### 5.3 编译器 `lib/theme/compile.ts`

两个产物，一个来源：

| 产物 | 用途 | 形态 |
|---|---|---|
| 运行时变量 | 实时预览 | `{ '--t-strong-color': '#c0392b' }` → 挂容器 style |
| 导出 CSS | 分享 / 备份 | `.themd-prose strong { color: #c0392b; font-weight: 700 }` 令牌与默认值解析合并后的完整文本 |

内置默认令牌表 `lib/theme/defaults.ts` 是编译的解析基准，也是「默认主题」的唯一事实来源。

## 6. 界面设计：主题工场（Theme Studio）

### 6.1 入口与形态

侧栏底部加「主题」入口（调色板图标），点击后**全屏接管主区域**（带「← 返回」），像进入一个独立页面。不放弹窗——三栏布局塞弹窗里太挤。

### 6.2 布局（三栏）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ← 返回   主题工场 · 我的主题 ●                 [明│暗]  [导入] [导出 ▾] │
├───────────┬──────────────────────────────────┬───────────────────────┤
│ 主题库     │                                  │  ▾ 加粗 strong         │
│ ● 默认     │        实 时 预 览                │  ──────────────────   │
│ ○ GitHub  │   （内置样例文档，一段文覆盖        │  字体颜色  [■ 深红] ⟲  │
│ ○ 墨间     │     全部元素，也可切「当前笔记」）   │  字  重   [700 ▾]     │
│ ─────────  │                                  │  字  号   [未设置]     │
│ 元素导航   │   # 一级标题长这样                 │  背景色   [未设置]     │
│ ▾ 基础     │   正文里有**加粗**、*斜体*、        │  ⋯                  │
│   正文     │   `行内代码` 和 [链接](…)          │                      │
│   段落     │                                  │  ⟲ = 单项恢复默认      │
│ ▾ 标题     │   > 引用块                        │                      │
│   H1…H6   │   ```ts                          │                      │
│ ▸ 行内     │   const x = 1                    │ [恢复此元素全部默认]    │
│ ▸ 列表     │   ```                            │                      │
│ ▸ 块级     │   | 表格 | 斑马纹 |               │                      │
└───────────┴──────────────────────────────────┴───────────────────────┘
```

- **左栏**：主题库（单选切换、复制/重命名/删除）+ 元素导航（按第 3 节分组折叠）。**所有主题都支持就地修改**：自定义主题的改动直接保存进主题本身；内置主题点「修改」自动先复制为「×× 副本」再编辑，内置原件不动。
- **中栏**：实时预览。默认渲染内置样例文档（一段话覆盖所有元素）；提供「用当前笔记预览」切换和明/暗切换。
- **右栏**：属性面板。选中哪个元素就显示哪组控件；每项可单独恢复默认；底部「恢复此元素全部默认」。

### 6.3 属性控件

每个可调属性对应一种控件类型：

颜色（取色器 + hex 输入）、字号/间距（数字 + 单位步进器，支持 px/rem/em/%）、字重（下拉 100–900）、字体（系统字体列表 + 自定义输入）、开关、下拉、对齐（分段控件）。未设置的属性显示「未设置」态，点 ⟲ 清除。

### 6.4 扩展机制：元数据驱动 UI（关键设计）

不写死任何界面。每个可定制元素注册一份元数据，右栏属性面板和左栏导航**全部由元数据自动生成**：

```ts
registerElement({
  id: 'strong',
  label: '加粗',
  group: 'inline',
  selector: 'strong',
  fields: [
    { key: 'color', label: '字体颜色', type: 'color' },
    { key: 'weight', label: '字重', type: 'font-weight', default: 700 },
    { key: 'size', label: '字号', type: 'size' },
    { key: 'bg', label: '背景色', type: 'color' },
  ],
})
```

以后加「脚注样式」「KaTeX 样式」= 各注册一行，UI 自动多出对应入口。这保证了「每一个 md 功能都能自定义」这条承诺在工程上是**可持续的**，而不是一次性堆一个巨型配置文件。

## 7. 导入与导出

| 能力 | 格式 | 期 | 说明 |
|---|---|---|---|
| 导出主题包 | `.themd.json` | P2 | 无损，含令牌与版本号，官方格式 |
| 导入主题包 | `.themd.json` | P2 | 与导出对称；版本号做迁移 |
| 导出 CSS | `.css` | P3 | 令牌解析成完整值的独立样式表；可选「Typora 兼容」选择器（`.themd-prose` → `#write`） |
| 导入 CSS | `.css`（Typora / github-markdown-css 等） | P3 | **尽力而为**：用原生 `CSSStyleSheet` 解析规则，凡目标元素在我们的覆盖矩阵内的声明 → 映射成令牌；映射不了的规则（伪元素、特殊选择器）原样收进该主题的「附加 CSS」。`#write` 等选择器自动改写。导入后弹出报告：「成功映射 32 条，8 条进附加 CSS」 |

管理导入预期是产品行为的一部分：Typora 主题带花哨效果很正常，能映射个七八成、剩余照常生效，就已经比竞品体验好。

## 8. 自定义 CSS（高级模式，P4）

每个主题可附一段原始 CSS：

- 编辑器用 CodeMirror（css 语言已注册，直接复用）；
- 自动限定作用域在 `.themd-prose` 内（文档告知约定：写 `strong { }` 即可，不必写前缀；注入时做包装处理）；
- 应用顺序：基础样式 → 令牌变量 → 附加 CSS，附加 CSS 最后生效，天然可覆盖前两者。

你判断得对——这块开放面大，放最后做。有前四期的令牌体系托底，大多数用户到不了需要手写 CSS 的那一步。
