# 开发日志

## 2026-10-30

### 侧栏抖动根治：退出 resizable-panels

- 上一版（像素 defaultSize + preserve-pixel-size）拖拽与记忆正常，但窗口缩放仍抖动：react-resizable-panels 是百分比引擎，缩放时浏览器先按旧百分比画脏帧，库再靠 JS/React 异步追赶校正，追赶永远慢合成器半拍。
- 侧栏改为固定像素宽的普通 flex 区块 + 自绘拖拽条 `SidebarResizeHandle`（Pointer Events + setPointerCapture），宽度变化由浏览器布局层逐帧保证，零 JS 参与不再抖动。
- 拖拽性能：逐条 pointermove 直写目标节点 `style.width`（rAF 合并到每帧一次），完全绕开 React 渲染；松手才进 React 状态并写入 `themd/ui-workspace/v1`。首版走 setState 每事件重渲染整棵树导致拖动卡顿，已废弃。
- 双击拖拽条恢复默认 288px。
- 折叠改纯状态驱动（`collapseSidebar` 事件 → setState），外层 `ResizablePanelGroup` 整个摘除；`react-resizable-panels` 仅剩分屏视图的编辑/预览分割在用。

### 侧栏宽度按像素记忆（已废弃方案）

- 侧栏不再随应用窗口整体缩放按比例变化：`ResizablePanel` 改用像素 `defaultSize` + `groupResizeBehavior="preserve-pixel-size"`（窗口缩放时增量全部给主区）。
- 拖拽后的宽度持久化到 localStorage `themd/ui-workspace/v1`（`src/app/workspace-preferences.ts`），重启后恢复。
- 落库只在用户手势结束时发生：`onLayoutChanged` 的 `isUserInteraction` 过滤折叠命令、窗口缩放等程序性变化，避免把 0/压缩值写进存储；库自带的百分比布局记忆（`useDefaultLayout`）因与「宽度不随窗口缩放」冲突而弃用。

### 架构重构收尾

- 将应用组合层、笔记领域、主题领域、渲染、导出、平台适配和 Tauri 命令拆分到独立模块。
- 笔记与主题改由 Controller 管理，IndexedDB 通过 Repository 访问，Web/Tauri 能力通过 Platform Gateway 访问。
- Tauri 文件、字体、PDF 命令拆分到 `src-tauri/src/commands/`，入口文件只保留 Builder、插件和命令注册。
- `docs/项目地图.md` 重写为唯一权威架构说明，`README.md` 与 `AGENTS.md` 同步更新。
