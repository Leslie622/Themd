# Themd 项目地图

> 本文件是 Themd 的唯一架构事实来源。修改目录、数据流、平台接口、持久化协议或开发命令时，必须同步更新本文件。

## 1. 项目定位与当前状态

Themd 是本地 Markdown 笔记本（仅 Tauri 桌面端，Web 路线已清除）：实时预览（Typora 式，TipTap 渲染态编辑）、CodeMirror 分屏/纯编辑、可视化主题工场、图片内嵌、Markdown/HTML/PDF 导出。**Folder-first「打开目录为工作区」**：目录即笔记本，树完全镜像磁盘，每个笔记都是工作区内的文件（Typora 语义）；编辑防抖写回、外部改动经递归监听自动重载（双向同步，文件即事实来源）。渲染已统一（docs/渲染统一方案.md）：全消费方走 `renderStaticHtml`（TipTap 管线），markdown-it 仅作测试 oracle。

当前为分层架构：笔记和主题由 Controller 管理，IndexedDB、文件、字体、窗口、PDF 均通过平台契约访问（platform 层只有 Tauri 实现）；旧 Store 文件只保留兼容导出入口，编辑器与外观偏好属于 UI 会话状态。新代码不得把 Zustand、IndexedDB 或 Tauri API 作为领域事实来源。

## 2. 运行时矩阵

单一环境:Tauri 2 桌面端。React + TipTap(实时预览)+ CodeMirror(分屏/纯编辑与内嵌代码块);笔记快照存 IndexedDB(WebView2 内)+ 文件绑定写回;文件对话框为 Tauri dialog + Rust 文件命令;字体由 Rust 枚举系统字体;PDF 走 WebView2 PrintToPdf。

开发端口固定为 `1420`，由 `vite.config.ts` 和 `src-tauri/tauri.conf.json` 共同约束。

## 4. 依赖方向与禁止依赖

- `domain` 只能依赖类型和纯函数，不得依赖 React、Zustand、DOM、Tauri。
- `application` 只能依赖 domain 和 platform contracts，不得直接调用 `indexedDB`、`localStorage`、`invoke`。
- `platform` 实现 contracts，可依赖浏览器 API、Tauri API 和 Rust 命令。
- `components` 通过 Controller、hooks 或 platform services 工作，不得裸调用 `invoke`。
- 图标体系三层：业务组件用 `@tabler/icons-react`（`Icon*` 命名，按使用语义选型，`size`/`className` props 与 lucide 同构）；`src/components/ui`（shadcn 生成物）保留 `lucide-react`——`shadcn add` 拷贝的官方源码自带 lucide 导入，不得手改生成物；代码块语言品牌图标用 `@icons-pack/react-simple-icons`（官方填色品牌图形，tabler 描边风不替代）。
- 业务事件使用 `AppEventBus` 或显式 props；禁止新增 `window.dispatchEvent` 业务事件。
- `src/store.ts`、`src/store-themes.ts` 是迁移兼容入口，新功能不应继续扩展它们。

## 5. 核心数据流

### 编辑与预览

```text
CodeMirror onChange
  → NotebookController.updateNote
  → NotebookSnapshot
  → IndexedDbNoteRepository.save(themd/notebook/v1)
  → preview debounce
  → renderMarkdown
  → ThemeCompiler
  → PreviewPane
```

预览区右侧大纲窄栏（TOC）：`modules/rendering/outline.ts` 的 `buildOutline` 复用 `md.parse` + `slug` 提取标题（id 与渲染 HTML 同源，跳转直接 querySelector）；窄栏可折叠（`useEditorPrefs.outlineEnabled`），滚动 rAF 前向扫描高亮当前标题（只读，不干扰 sync-scroll）。

### 实时预览视图（live，Typora 式边写边渲染）

顶栏视图组第 4 项（`ViewMode = 'live'`，AppShell）：单栏 CodeMirror + `src/lib/markdown-live-preview.ts` 装饰层。文档仍是纯 Markdown 源码（写回/同步/导出管线零改动），显示层按语法树（`ensureSyntaxTree`，GFM）出装饰：标题吞 `#` + 行级字号、强调/行内代码藏定界符加样式、链接保文本藏 `[](url)`、图片整段换内联 `<img>`（src 经 `resolveImageSrcSync`，与预览同源）、无序列表换 bullet/任务标记换可点 checkbox（点击改写 `[ ]`↔`[x]`）、引用行加边框、`---` 换水平线、围栏代码块用**块级 replace** 连换行吞围栏行。光标压住的行一律露源码；隐藏区间走 `atomicRanges`。与 image-decorator 同理必须 StateField（ViewPlugin 装饰长行 LineGapWidget 看不见）；启用时经 EditorPane 的 compartment 与 `imageChipExt` **二选一**（都 replace 图片标记范围）。视图模式记忆在 `themd/ui-preferences/v1` 的 `viewMode`（v7，App 初值取偏好、切换写回）。

### 文件绑定双向同步

```text
写入向:updateNote / bindNoteToFile
  → 500ms 防抖 → FileLinkGateway.writeTextFile → Rust 原子写(tmp + rename)
  → lastWritten 记录内容,用于抑制自家写回触发的 watcher 回声
读取向:Rust notify 对工作区根**递归**监听 → 防抖 300ms
  → emit 'fs-changed' → FileLinkGateway.onFsChanges → handleFsEvents
  → modified:与当前内容一致或为自家回声则忽略;干净静默重载;
    有未写回编辑则发 fs-conflict 事件,UI 弹窗二选一(重载磁盘版/保留本地写回)
  → removed:标记 fileMissingIds(继续编辑写回自动重建并解除)
  → renamed:改绑 sourcePath,非自定义标题跟随文件名
落盘时机:500ms 防抖、Ctrl+S(活动笔记立即写回)、窗口失焦/切后台 flushAll、
  托盘退出前 Rust 发 'app-before-quit' 并 sleep 600ms 留写回窗口
写回失败:经 appEvents 'write-failed' 通报 UI toast(带「重试」= flushNote),
  同一文件只报首次、写成功后解除;失败保留 dirty 状态(下次编辑/重试继续写),
  不另建重试队列
```

**打开工作区**：侧栏工作区胶囊 → 系统目录选择器（或最近列表重开）→ `openWorkspace(root)` = Rust `read_folder_notes(root, with_content=false)` **懒加载元数据扫描**（Typora 语义：只取文件名/路径不读正文，大目录秒开；非 UTF-8 判定推迟到按需读取）→ 整表替换笔记列表（同路径笔记按 sourcePath 复用，id/笔记主题跟随，重扫不丢状态；新笔记 `content: ''` + `contentLoaded: false`）→ 重建文件夹（目录去重 + **祖先链补齐到工作区根**：无直接笔记的中间目录也是树节点）→ `watchWorkspace(root)` 递归监听。**正文懒加载**：`Note.contentLoaded === false` 表示仅元数据；激活（`setActive`）时经 `ensureNoteContentLoaded` 读盘填充（in-flight 去重，失败标失联）；未加载的笔记编辑器不挂载（AppShell 用 Spinner 占位，防空内容覆盖磁盘）、`updateNote` 有兜底拒绝；快照对未加载笔记只存元数据；外部 modified 事件对未加载笔记不读盘比对（激活时天然读最新版）。**侧栏搜索只匹配标题**（懒加载后未打开笔记内存无全文）。工作区记忆（current + 最近 5 个）在 `themd/ui-workspace/v1`，启动时自动重开。**新建笔记** = `createNoteInDir`（工作区根或右键指定文件夹）：`unique_destination` 求无冲突路径 → 立即写盘绑定，不再有「未绑定笔记」概念（v≤3 的库内笔记在 hydrate 时按用户决定丢弃）。**绑定写盘/移动换目录时图片随迁**（组合根注入 `src/lib/note-assets.ts`）：正文引用的 `assets/…` 图片按「旧笔记目录 → 全局图片根」的顺序用 `read_binary_file` + `write_image_file` 原样字节复制到新笔记目录（目标同名跳过幂等、单张失败不阻塞）；首绑走 `bindNoteToFile`、移动走 `moveNoteToFolder` 自做迁移。冲突处置入口在 `NotebookController.reloadNoteFromDisk` / `keepLocalNote`。

### 文件夹 = 目录（Typora 文件树模型，仅桌面端）

```text
归属:绑定笔记 ∈ 其所在目录的文件夹(派生,不存 folderId)
不变式:publish 时惰性补建「绑定笔记目录 → Folder 实体」
移动到文件夹:记 wasDirty → cancelPendingWriteBack → migrateNoteAssets(图片随迁)
  → move_note_file(重名自动后缀) → 改绑 sourcePath;脏笔记立即补写新路径(编辑随笔记走,
  抢在 watcher 事件前落盘抑制回声)
重命名笔记:绑定笔记 = rename_note_file 同目录改名(重名自动后缀) → 标题/路径跟随实际落点;
  未绑定笔记仅改显示名。绑定笔记标题恒等于文件名(内容编辑不派生标题)
  → 有未写回编辑的笔记立即补写新路径
删除笔记:绑定笔记 = trash_file 把磁盘文件移入系统回收站(可恢复,幂等);
  未绑定/失联笔记仅从应用移除。外部删除:干净笔记直接从列表移除(树=磁盘),
  有未写回编辑的标失联走横幅自救
外部新建:Create 事件映射为 modified,前端按路径找不到笔记 → 工作区内
  的 .md/.markdown/.txt 自动入库(标题=文件名,整棵递归)——树=磁盘实时视图
外部目录重命名:watcher 报目录级 renamed(单文件事件不会来),
  按「严格位于 oldPath 之下」批量换算 folders + notes(路径相等 = 单文件,走文件级)
```

设计决定：**删除文件夹 = 删除磁盘目录**（对齐 Typora 文件树，用户确认后经 `delete_directory` 移入回收站），其下子文件夹与笔记从应用一并移除——文件已不存在，笔记不能留着假装还能编辑；空文件夹照常显示（空文件夹在文件树里就是可见的）。路径比较一律经 `src/shared/paths.ts` 的 `normalizePath`/`isPathUnder`（大小写 + 分隔符不敏感），展示保留原串。

### 工作区（folder-first）

```text
打开:侧栏胶囊/空态 CTA → pickDirectory → openWorkspace(递归导入+递归监听)
记忆:themd/ui-workspace/v1 {current, recents[≤5]};启动自动重开,重扫按
  sourcePath 幂等复用笔记 id
清除:closeWorkspace → watchWorkspace(null) + 清空笔记列表
新建:工作区根(顶栏/侧栏「新建」)或文件夹右键「在此文件夹新建笔记」,
  都走 createNoteInDir(unique_destination + 写盘绑定)
```

工作区外不存在笔记:watcher 只递归监听工作区根,`importExternalCreated` 仅收根下笔记扩展名文件;「导入文件/文件夹」按钮已随库内模式一起删除(目录即笔记本,文件放进去就出现)。

### 主题

```text
ThemeStudio
  → ThemeController command
  → ThemeSnapshot
  → IndexedDbThemeRepository.save(themd/themes/v1)
  → compileTokens
  → .themd-prose CSS variables
```

主题工场（`src/components/theme/ThemeStudio.tsx`）三栏布局：左=主题库+元素导航（由 `lib/theme/elements.ts` 元数据驱动，三栏头部同为 h-14 一条线；**两个分区独立滚动**——主题库列表自滚动且最多占左栏 45% 高，元素导航 flex-1 自滚，互不挤占），中=预览，右=属性面板（只放令牌控件：恢复默认、附加 CSS，无说明文案；亮/暗令牌套切换已按用户要求移除——暗色套随主题文件参与编译，但工场内暂无编辑入口）。主题库行：名称后跟 shadcn Badge 小标签（**内置**灰色 secondary、**使用中**界面强调色 `--chrome-accent` 淡底着色；行本身无 hover/选中底色，激活态仅靠「使用中」tag 表达）；非激活主题行内常显 outline「使用」小按钮；副本语义只由名字后缀「xx 副本」体现（`copy()` 命名），不渲染 tag；**激活不变式**：新建/创建副本/内置编辑自动复制/导入一律不改 `activeId`，「使用中」仅经显式 `setActive`（行内「使用」按钮或右键菜单）切换；新建也不切 `editId`（预览/编辑对象不被强行换成白纸新主题，编辑 = 点列表行）；操作入口两份共用一套 `ThemeMenuItems`（Sidebar 的 parts 范式）——行尾 hover 显形的「⋯」下拉与**整行右键菜单**（shadcn ContextMenu 包行，只拦右键不影响行内左键）；重命名走 Dialog 弹窗（侧栏改笔记名称同款，不用内联输入——菜单关闭后 WebView2 程序性抢焦）。顶栏右上角与主页同款 ghost 图标按钮（导入主题包/CSS；导出下拉：.themd.json / 可移植样式包（Typora/VSCode/GitHub/通用，`lib/theme/portable-css.ts`）——P3 的 `.css` 平铺导出于 2026-11-04 退役，`exportThemeCss`/`EXPORT_LIST_SCOPE`/`cssPropFor` 已随删）。中栏头部 h-14 与右栏头部等高，预览三模式用 shadcn Tabs：**专注样例**（默认，`lib/theme/element-samples.ts` 按左侧选中元素渲染一段带上下文的样例文稿，跟随元素切换）、**全内容样例**（`lib/theme/sample.ts` 覆盖全部常用 Markdown 元素的标准完整文档）、**导入笔记**（`NotePicker` 从当前工作区选一篇笔记，内容复制为本地编辑副本，不写回源文件——预览区整体换成 `LiveEditorPane` 渲染态实时编辑（Typora 式单栏，`noteThemeId=正在编辑的主题`，编辑即所见，右侧调令牌实时生效；绑定磁盘文件的笔记经 `setActiveNoteDir` 临时切换图片解析基准，离开导入预览时还原为活动笔记；「选择元素」在此模式置灰）。颜色令牌的回落色从中栏预览 DOM 实测（`lib/theme/color-fallbacks.ts`），取色器拖动经 CSS 变量直写预览容器实现零渲染跟手。字体令牌（root/heading/inlineCode/codeBlock 的 font）复用设置模块 `FontField` 弹窗（本机字体列表+搜索+自由输入），代码类令牌以等宽语境预览。

### 图片

图片存储三模式（`themd/ui-preferences/v1` 的 `imageMode`，默认 `assets`）：
- **本地文件夹（默认，仅桌面端）**：图片**原样字节**落盘（不重编码，保真优先）写入 `${assetsRoot}`，正文引用 `assets/<名>-<随机8位>.<原扩展>` 相对路径；`assetsRoot` 空 = 平台默认（桌面端应用数据目录 `appDataDir()/assets`），**绑定磁盘文件的笔记例外**——插图落笔记自身目录下 `assets/`（随文件走）。落盘经 FileGateway.`writeBinaryFile` → Rust `write_image_file`（`Vec<u8>` IPC 二进制）；`tauri.conf.json` 的 `assetProtocol`（scope `**`，绑定笔记的图片可来自任意用户目录）供 `convertFileSrc` 渲染，`src/lib/image-src.ts` 在 markdown 渲染时把相对路径同步改写为 asset:// 地址（`initImageSrcResolver` 于 main.tsx 预取）：绑定笔记的相对路径（`assets/…`、`./x.png`、`sub/x.png`）一律相对笔记自身目录解析（App 在活动笔记切换时经 `setActiveNoteDir` 注入基准），库内笔记仅 `assets/` 相对全局根。设置里可改目录/恢复默认/打开目录（opener 插件）；编辑器内 Ctrl+点击 assets/ 路径在文件管理器中定位图片。
- **上传图床（remote）**：压缩（长边 1600/WebP 0.82）后上传拿外链，正文写 `![alt](https://…)`；失败即中止该张插入，不回落。服务商二选一（`uploaderProvider` + 各凭据字段，token 明文本机保存，Typora/PicGo 式）：
  - GitHub 仓库：`PUT repos/{repo}/contents/assets/{name}`（token 需 Contents 读写权限，取 `content.download_url`）
  - PicGo 本地桥：`POST {picgoUrl}`（默认 `127.0.0.1:36677/upload`），body `{list:[{base64,fileName}]}`——用户在 PicGo 里配任意对象存储
  - 上传协议统一在 `src/platform/web/uploader-gateway.ts` 纯函数（`uploadWith` 注入 fetch）；Tauri 实现注入 tauri-plugin-http 的 fetch（Rust 层请求绕 CORS，capability 白名单 api.github.com/127.0.0.1/localhost），Web 实现注入原生 fetch（GitHub 实测 `Access-Control-Allow-Origin: *`，Web 端可用）。contract 在 `src/platform/contracts/uploader-gateway.ts`。配置 UI 在设置抽屉的 `UploaderField`（`src/components/settings/UploaderField.tsx`，FontField 式槽位：触发器回显当前配置，服务商/凭据/测试上传收进 Dialog；SM.MS/s.ee 路线已在偏好 v6 移除，存量 provider 回落 github）。
- **内嵌（可选）**：压缩为 data URL 内嵌正文，单文件自包含。
- 编辑器徽章（`src/lib/image-decorator.ts`）只隐藏 data URL，相对路径/外链直接显示文本；预览/导出对三种形式均原样输出，`<img>` 相对路径按应用根/导出位置解析。
- **预览区图片灯箱**（`src/components/ImageLightbox.tsx`）：笔记预览（`PreviewPane`）与主题工场预览（`ThemeStudio` 的 `ThemeScopedPreview`，`inspect` 模式不启用）里点击 `<img>` 事件委托打开全屏灯箱（`collectLightboxState` 收集全部 `<img>` 并按被点图定位）——可在同一篇的多张图之间左右切换（‹ › 箭头/方向键）。第三方库 yet-another-react-lightbox + Zoom/Captions 插件：纯滚轮缩放（`scrollToZoom`，上限 4x 图片像素尺寸，注意 `maxZoomPixelRatio` 不能传 -1，会把 maxZoom 算成 1 导致缩放按钮永远 disabled；`minZoom: 0.5` 放开缩小下限，默认 1 = 初始即最小不能缩；`wheelZoomDistanceFactor: 800` 让每格滚轮约 ±20%，默认 100 一格就 ×2；滚轮缩放走 rapid 分支无库动画，由 `image-lightbox.css` 给 `.yarl__slide_wrapper` 的 transform 加 150ms transition 补平滑；拖拽平移仅当图片放大到超过视口才有余量（`changeOffsets` 钳制，YARL 正确行为）、`carousel.padding: 64px` 让初始 fit 四周留白不铺满视口、双击放大、`closeOnBackdropClick` 点空白关闭、Esc/关闭按钮；**旋转/下载为自定义工具栏按钮**——旋转按 slide 序号记忆（90° 递增，transform 写在 `.yarl__slide_image` 上与 wrapper 的缩放/平移互不干扰，换一组 slides 复位），下载走 fetch→blob 触发（官方 Download 插件只对同源 URL 有效；跨域拿不到字节时回落 `<a download>` 浏览器默认行为），文件名从 src 路径/alt 推导；观感经 `image-lightbox.css` 用应用 shadcn 令牌（popover/radius/border）定制；**全部按钮为 shadcn Button**——经 YARL 的 `render.buttonZoom/buttonPrev/buttonNext` 与 `toolbar.buttons` 定制口替换（放大/缩小/关闭/前后切换，tabler 图标，常显深色磨砂圆底保证白图上可见；导航箭头 size-10、内收 16px，垂直居中用 wrapper flex 而非 `-translate-y-1/2`——shadcn Button 按压反馈 `active:translate-y-px` 会覆盖 translate 变量导致按钮下坠半屏；`.yarl__toolbar` 补 4px gap 统一右上角按钮间距）。src 直接取 `img.currentSrc`（渲染期已由 `resolveImageSrcSync` 解析为 asset:///data/https），图片包在 `<a>` 内时 `preventDefault` 拦导航；仅改交互不改渲染规则，standalone HTML 导出不受影响。
- 存量图片不迁移。图片存储三模式均可用。

## 7. 持久化与迁移

新协议使用独立 IndexedDB 数据库 `themd-architecture`：

```text
themd/notebook/v1（schemaVersion = 4）
themd/themes/v1
```

笔记快照只包含 `schemaVersion`、`notes`、`folders`，定位是**磁盘的缓存**：重启后按工作区记忆重扫磁盘重建。`Note.sourcePath` 为必填（v4：每个笔记都是文件），标题恒等于文件名主干；活动笔记与 `fileMissingIds`（文件失联标记）属于 UI 会话；工作区目录与最近列表在 `themd/ui-workspace/v1`。**v3：文件夹 = 磁盘目录**——`Folder {id, name, path, order}`（层级由路径前缀派生，不存 parentId），控制器在 `publish` 时惰性补建（不变式：每个笔记的目录都有 Folder 实体）。**v4：folder-first**——`titleCustom` 与库内笔记概念删除；v≤3 迁移：无 sourcePath 的库内笔记直接丢弃（用户拍板当测试数据），绑定笔记保留。主题快照只包含用户主题和 active id。编辑器默认使用打包的 JetBrains Mono（西文）与 HarmonyOS Sans SC（中文）。旧键 `md-notebook`、`themd-themes`、`themd-editor`、`themd-appearance` 不再读取——旧版数据恢复入口与 `legacy-import` 模块已删除，应用只按当前协议启动。主工作区：侧栏是固定像素宽的普通 flex 区块（`src/components/SidebarResizeHandle.tsx` 自绘拖拽条），宽度记忆在 localStorage `themd/ui-workspace/v1`（`src/app/workspace-preferences.ts`），窗口缩放零 JS 参与不抖动；侧栏**不**参与 `react-resizable-panels`——其百分比引擎在窗口缩放时靠 JS 追赶校正会产生脏帧抖动，该库现仅用于分屏视图的编辑/预览分割与预览区大纲分栏（shadcn `ResizablePanel`；注意 v4 尺寸字符串不带单位才是百分比，`"22%"` 解析不对）。

设置抽屉（`src/components/SettingsSheet.tsx`）分区：主题、界面字体、编辑器。字体槽位（西文/中文）点击打开 `src/components/settings/FontField.tsx` 的 Dialog：完整本机字体列表（可搜索、逐行复制族名、点击选中）、底部自由输入框支持逗号分隔多族名（font-family 语义，浏览器按字符逐个回落）。字体枚举与可用性检测在 `src/lib/theme/font-list.ts` 与 `src/components/settings/is-font-available.ts`，共享缓存 hook 在 `src/components/settings/use-local-font-list.ts`。「未安装」提示按整条 font-family 栈逐族检测——任一真实族名（排除 sans-serif 等通用关键字与 `-apple-system` 类私有前缀）可用即算已安装，避免长栈值在部分平台恒误报。

滚动条显隐全产品统一「滚动浮现 / 静止淡出」（时序单一来源 `src/components/scroll-visibility.ts`）：滚动容器滚动期间挂 `.osb-active`，静止 900ms 淡出；hover **不**点亮（不滚动就不出现），可见期间悬停滚动条则保持可抓取。两套实现共用同一节奏与配色：Radix 浮动滚动条统一经 `AutoHideScrollArea` 包装（侧栏、预览/大纲、实时编辑、设置抽屉、主题工场、字体弹窗），显隐由包装组件在 Root 上维护 `.osb-active`；**CodeMirror 编辑器不用原生滚动条**——`.cm-scroller` 经 `scrollbar-width: none` 整体退场（设标准属性后 `::-webkit-scrollbar` 伪元素对该元素失效），改挂 `src/components/cm-scrollbar-overlay.tsx` 自绘的 DOM 浮动滚动条（纵/横双轴），其 DOM 结构（`data-autohide` + `scroll-area-scrollbar`/`scroll-area-thumb` 槽位）与 AutoHideScrollArea 完全同构，显隐/配色/hover 加深复用同一套 CSS——原生伪元素滚动条的绘制在不同 Chromium 环境下不可控（IAB 与 WebView2 表现不一致），故编辑器侧不与之混用；其余原生 `::-webkit-scrollbar`（弹层菜单、代码块）由 `main.tsx` 挂载的 `installGlobalScrollbarFade` document 捕获级 scroll 监听统一接管（scroll 不冒泡但走捕获，一个监听覆盖所有滚动容器）——thumb 默认透明只留轨位（布局占位不变不抖动），点亮才上色（index.css 全局滚动条段）。轨宽全产品统一 8px、点亮后可见 thumb 6px（Radix 侧经 AutoHideScrollArea 的 ScrollBar className 覆盖收窄；编辑器 overlay thumb 再收 1px 至 5px 视觉对齐）；配色为 muted-foreground 的 color-mix 双档——点亮 25%、hover 40%（DOM 与原生伪元素两处规则同值）。分屏视图的同步滚动会让两侧滚动条同时点亮，属预期行为。

悬停提示全产品统一走 shadcn Tooltip，业务代码**禁用原生 `title` 属性**：统一经 `src/components/Tip.tsx` 的 `Tip`（`TooltipTrigger asChild` 包住触发元素 + 自带 `TooltipProvider delayDuration=300`，任何挂载点可用；触发元素必须可转发 ref——shadcn Button/Radix 原语/原生元素均可，可与其他 Radix `asChild` 触发器嵌套合并，如菜单项、SelectTrigger、PopoverTrigger）。适用三类场景：图标按钮（右键菜单网格、灯箱、取色器）、截断文本展示全量（侧栏路径、大纲 TOC、设置回显）、表单控件「未设置」语义提示（FieldControls/FontField——label 条件为 undefined 时只不渲染内容，触发器结构不变，Input 不重挂载不丢焦点）。图标按钮的 `aria-label` 与 tooltip 并存（无障碍名不依赖 hover）。AppShell 顶栏 `IconTip` 是 Tip 的 `side="bottom"` 别名。

## 8. Tauri 命令

Rust 命令在 `src-tauri/src/commands/` 提供包装实现，由 `src-tauri/src/main.rs` 注册；新增前端命令调用统一经 `src/platform/tauri/commands.ts`。应用为「关闭到托盘」的常驻进程，`main.rs` 第一个插件注册 `tauri-plugin-single-instance` 单实例锁——再次启动只唤起已有实例，禁止多开：

| 命令 | 用途 |
|---|---|
| `list_system_fonts` | 枚举系统字体族名 |
| `read_folder_notes` | 递归扫描 Markdown 文件夹（含 `filePath` 绝对路径，非 UTF-8 不返回）；`with_content=false` 只回元数据不读正文（懒加载），跳过隐藏目录与 `node_modules`/`target`/`dist`/`build`/`out` 等依赖构建目录，async + spawn_blocking 不占主线程 |
| `read_text_files` | 读取用户选中的多个 Markdown 文件（同上） |
| `read_text_file` | 严格读取单个文本文件（绑定笔记外部改动重载用，非 UTF-8 报错） |
| `read_binary_file` | 读取二进制文件（绑定写盘/移动迁移 assets 图片用，与 `write_image_file` 对偶） |
| `delete_file` | 删除单个普通文件（通用文件删除能力，当前无前端消费方；目录一律拒绝） |
| `trash_file` | 删除文件（笔记删除 = 磁盘文件移入回收站，可恢复；幂等——文件已不存在视为成功） |
| `move_note_file` | 移动文件到目标目录（「移动到文件夹」= 物理搬文件；重名自动 -2/-3 后缀，返回实际落点；跨盘回落 copy+delete） |
| `rename_note_file` | 同目录重命名文件（笔记重命名 = 磁盘文件改名；重名自动后缀，返回实际落点） |
| `rename_directory` | 重命名目录（文件夹重命名；仅同盘 rename，跨盘明确报错） |
| `delete_directory` | 删除目录（文件夹删除 = Typora 文件树语义；整棵**移入系统回收站**可恢复，`trash` crate 实现；盘符根一律拒绝） |
| `unique_destination` | 求目录下无冲突文件路径（非法字符过滤 + 重名后缀；移动即绑定/文件夹内新建用） |
| `write_text_file` | 写入 Markdown/HTML 文件（原子写：tmp + rename，失败回落覆盖） |
| `watch_workspace` | 工作区根递归监听（`commands/watch.rs`，notify `RecursiveMode::Recursive`，防抖 300ms 后 emit `fs-changed`；null = 停止）。async + spawn_blocking：对大目录建 watch 不占主线程 |
| `export_pdf` | 调用 WebView2 PrintToPdf |
| `position_tray_menu` | 自绘托盘菜单落位：前端量出菜单尺寸（逻辑像素）回传，Rust 按光标所在显示器缩放**估计**换算物理尺寸、钳回显示器边界后落位显示窗口（`commands/tray.rs`） |
| `resize_tray_menu` | 自绘托盘菜单尺寸校正：显示后前端按窗口真实 `devicePixelRatio` 换算物理像素回传纠偏（缩放估计与 WebView 实际渲染缩放不一致时首帧会裁边）；仅对可见窗口生效，失焦已藏的窗口不复活 |
| `close_tray_menu` | 收回托盘菜单窗口（Esc / 选中菜单项时前端调用） |
| `tray_menu_action` | 自绘托盘菜单项动作：`show` = 唤起主窗口，`quit` = 冲刷写回后退出 |

Tauri 的托盘、窗口关闭到托盘和自定义窗口控制属于 platform 层，不进入领域模块。**托盘右键菜单为自绘**（原生 Win32 菜单样式不可定制，只能跟随系统深浅色）：`tray.rs` 不绑定原生菜单，右键按下开合常驻隐藏的第二个 WebView 窗口 `tray-menu`（无边框透明置顶、skip taskbar、启动即建保证秒弹），内容是 shadcn `DropdownMenu` 受控弹出（`src/components/TrayMenuWindow.tsx`），主题令牌与主窗口同一套、深浅色跟随 `store-appearance`。开合链路：托盘右键 Down → Rust `emit_to('tray://open', 光标)` → 前端量 `offsetWidth/Height` 经 `position_tray_menu` 回传 → Rust 按显示器缩放估计换算落位 + show + set_focus → 前端挂 `ResizeObserver` 按窗口真实 `devicePixelRatio` 经 `resize_tray_menu` 校正一次（observe 立即回调；Rust 的缩放估计在高 DPI 屏可能拿不准，错了一帧内纠回）。窗口失焦由 `window.rs` 直接隐藏（点外部关闭语义），前端监听同一事件收回菜单态。左键单击无条件唤起主窗口（show/unminimize/set_focus，单实例锁回调复用同一 `summon_main`）。菜单的「退出」与旧原生菜单同走 `quit_gracefully`（emit `app-before-quit` + 600ms 写回窗口）。托盘菜单能力 contract 在 `src/platform/contracts/tray-menu-gateway.ts`，Tauri 实现装配于 `create-platform-services.ts`。开机自启经 `tauri-plugin-autostart`（写 HKCU Run 键，带 `--minimized` 参数自启时窗口直接进托盘）：contract 在 `src/platform/contracts/autostart-gateway.ts`，Tauri/Web 实现装配于 `src/platform/create-platform-services.ts`，设置抽屉「主题」分区暴露开关（仅桌面端渲染，状态以系统注册表为准）。

- 基础正文样式在 `src/styles/theme-base.css`，作用域为 `.themd-prose`。
- 画布背景令牌 `app.bg`（`--t-app-bg`，UI 名「画布背景」）值为完整 CSS background（颜色/渐变/`url(...)`），铺正文纸张之外的预览区整体——消费方为预览滚动容器（ThemeScopedPreview / PreviewPane / LiveEditorPane）与独立 HTML 的 body；`root.bg` UI 名「纸张颜色」（正文这页纸的底色）。工场控件类型 `background`（色块+hex+图片按钮——图片经 `fileToBackgroundDataUrl` 压成 data URL 内嵌进主题值，`pickImageFile` 选文件）；CSS 导出时 `app.*` 令牌分流到 `body` 块。
- 主题元数据在 `src/lib/theme/elements.ts`，主题工场由元数据驱动。
- 独立 HTML 导出必须复用 Markdown、令牌和附加 CSS 管线。

## 12. 已知约束与坑位

- `react-resizable-panels` 仅用于分屏视图编辑/预览分割：`orientation`，百分比尺寸传字符串，像素约束传数字。侧栏不要放回它的 Group——百分比引擎窗口缩放抖动，见第 7 节工作区说明。
- shadcn 组件可能从独立 `cn` 包导入，业务代码使用 `@/lib/utils`，不要强行统一。
- `verbatimModuleSyntax` 和 `erasableSyntaxOnly` 开启，类型必须 `import type`，避免参数属性语法。
- 高亮语言按需注册，禁止改回全量 highlight.js。
- Tauri 自定义窗口使用 `decorations: false`，窗口按钮必须保持在拖拽区之外的可点击区域。
- 窗口配置 `dragDropEnabled: false`：Tauri 默认在 WebView 层拦截文件拖放（拖图片进编辑器收不到 drop 事件），关闭后由前端 `domEventHandlers` 的 drop/dragover 自行处理；设置抽屉打开时顶栏拖拽区被 overlay 遮挡，抽屉头部已补 `data-tauri-drag-region`。
- `src-tauri/gen/schemas/*` 可能因 Tauri 运行时更新，审查时区分生成物和业务改动。
- 原生右键菜单（WebView2/浏览器默认菜单）在 `src/main.tsx` 全局 `contextmenu` preventDefault 禁用（input/textarea 豁免保留原生复制粘贴）；编辑器区域的右键由 shadcn ContextMenu 接管（`EditorPane`，仅「插入图片」）。DevTools 不受影响：调试构建 F12 / Ctrl+Shift+I 打开，右键「检查」已随原生菜单消失。
- opener 插件 `open_path` 命令在 Rust 侧用 capability 里的 scope 条目构建 fs 白名单校验路径，裸 `opener:allow-open-path`（不带 scope）= 空白名单 = 任何路径都 `ForbiddenPath`；必须写成带 `"allow": [{ "path": "**" }]` 的对象权限（图片目录用户任选，不能收窄）。`reveal_item_in_dir` 不做 scope 校验，无此问题。
- 文件绑定回声抑制在**前端**：Rust watcher 不区分改动来源，应用自己写回也会触发 `fs-changed`。modified 靠「磁盘内容 = 笔记当前内容」或「= lastWritten 最近一次写回内容」过滤；**removed 事件不直接相信**——原子写的 rename 替换目标在 Windows 会被报成 removed，前端先 `readTextFile` 验证，读得到按 modified 判定、真读不到才标记失联。改这段逻辑时注意顺序（先回声后脏判定），否则编辑中会误弹冲突窗/误报失联。
- 非 UTF-8 文件不绑定（Rust `read_folder_notes`/`read_text_files` 对 lossy 解码的文件不返回 `filePath`），否则绑定写回会把降质内容写回毁掉原文件。`read_text_file` 重载同样严格 UTF-8。
- `notify-debouncer-full` 0.6 起 `Debouncer` 自带 `watch/unwatch`（`.watcher()` 已废弃返回 unit），事件结果是 `Result<_, Vec<Error>>`；notify 一律经 `notify_debouncer_full::notify` 路径引用，避免 notify 双版本类型冲突。
- 目录级 renamed 事件的判定是「严格位于 oldPath 之下」——路径完全相等是单文件重命名（标题跟随文件名），混用会导致文件重命名被当成目录处理、标题不跟随。
- `rename_directory` 只做同盘 rename；跨盘需要复制整棵目录树，明确报错而不是静默复制。`move_note_file` 跨盘回落 copy+delete（先复制成功再删源，失败时源仍在）。
- 主题工场字段占位符的单一来源是 `src/lib/theme/defaults.ts`（`THEME_BASE_DEFAULTS`，令牌 → `theme-base.css` 的 `var()` 回落值镜像）：`elements.ts` 不再手写 placeholder，渲染端经 `placeholderOf(key)` 查表。一致性由守门测试 `defaults-sync.test.ts` 机械锁定（解析 CSS 源码逐项比对），改 CSS 回落值不同步常表（或反之）测试立刻红。颜色/字体占位符不走常表——运行时实测（`resolveFallbackColors`/`resolveFallbackFonts`）。新增令牌流程：tokens.ts 加键 → theme-base.css 消费 → elements.ts 加字段 → defaults.ts 登记回落值（漏登记测试红）。曾因行高 1.75→1.6、段间距 1.25em→0.8em 密度调整漏改占位符而回显失真，治本前靠人肉同步。
- 主题工场预览、主预览（PreviewPane）、实时编辑器三处渲染出的 `<a href>` 点击默认行为是 WebView 直接导航、会替换整个应用页面——三处都必须拦截（preventDefault + `platformServices.files.openUrl` 走系统浏览器；TipTap 侧是 `Link.configure({ openOnClick: false })`，Tauri WebView 无弹窗拦截，`window.open` 会退化成当前窗口导航）。新增渲染 HTML 的面板时同样要拦。
- TipTap Strike mark 渲染 `<s>`，markdown-it/静态预览输出 `<del>`：所有 `del.*` 令牌的 CSS 选择器和回落测量目标必须同时覆盖两个标签（曾因只写 `del` 导致删除线全部设置在实时编辑器不生效）。
- **GFM Alerts 提示块**（`> [!NOTE]` 五类，非标准 Markdown、GitHub 惯例，降级=普通引用块）三面实现不同但共用 `--t-callout-*` 令牌：五类强调色一色三用（边框/标题/背景 color-mix 派生，深浅由 `callout.bgOpacity` 百分比参数化），形态参数（边框粗细/圆角/内边距）为五类共用：静态/导出侧 `modules/rendering/gfm-alerts.ts`（vendored core 规则，blockquote 变身 `div.themd-callout-<type>` + `themd-callout-title` 图标标题行，标记必须独占 blockquote 首段）；实时编辑器 `live-editor/infrastructure/callout-blockquote.ts`（**Blockquote.extend + `alertType` 属性**，不新增节点类型；marked 把段内多行文本放在单个 text token 里，剥离即改 text；renderMarkdown 回写 `> [!TYPE]` 首行；NodeView 仅 alertType 块生效、普通引用返回 null 落回默认 DOM——PM 运行时支持 factory 返回 null，类型未建模需断言）。改 gfm-alerts 规则时注意两坑：配对 blockquote_close 必须深度扫描（callout 里可以有多段/嵌套）；标记行与正文同段时标题要**前插**而非整段替换（否则吃掉正文），渲染依据是 `inline.children` 不是 `inline.content`（inline 解析先于 core 规则）。
- **取色器**是 @uiw/react-color-sketch（Sketch 风格：面板/色相/透明度/hex/rgba/预设色板全内建）包在 shadcn Popover 里（`SketchPopover`，`FieldControls.tsx`），全字段共用；Sketch 自带的框/投影经 `--sketch-*` CSS 变量压平（不压会与 Popover 的框叠成双层）。拖动沿 `submitThrottled` 管线：色块直写 + rAF 合拢 + 200ms 收口。**画布背景（app.bg）特殊**：消费点是预览滚动容器的 React 内联样式（非 CSS 变量消费者），实时预览必须**直写容器 background**（`[data-app-canvas]` 定位），走 .themd-prose 变量的通用管线对它无效；此前每次取色都编译+整树重渲染=卡顿主因。
- **图片是块级元素**（Tailwind preflight `img { display: block }`），水平对齐只能走 `margin-inline`（左 `0` / 中 `auto` / 右 `0 auto`，单令牌 `img.align`），text-align 对块级图无效；vertical-align 同理无语境（不提供垂直对齐令牌）。分割线的 margin/padding、图片宽高（`img.width/height`，未设 = auto）均为普通令牌；上下外边距 `img.margin` 走 `margin-block`（与对齐的 `margin-inline` 正交长手，四向盒的左右两格会是死控件，故做成单值 size）；阴影 `img.shadow` 存完整 box-shadow 值，编辑经 `ShadowInput`（X/Y/模糊/扩散四格 + 颜色，全零 = 删令牌回落 none），导出/导入对控件零感知。
- **表格单元格边框**是三个结构化令牌（`cell.rowLine` 行横线开关 / `cell.colLine` 竖线开关 / `cell.borderWidth` 线宽），颜色**统一吃 `table.borderColor`**——单元格边框颜色不得自带：collapse 模式下同宽的单元格边框在冲突解决中压过表格自身边框，简写省略颜色时回落 currentColor 会把外围边框整圈带走（曾因此「边框颜色只作用于上边框」——顶边因表头 `border-top: none` 让位才幸免）。旧自由文本令牌 `cell.border` 已废弃不迁移（令牌协议：未知键静默忽略）。CSS 导出统一走可移植样式包（令牌内联 + theme-base 全文，元素落点由规则天然保证）；曾经令牌值平铺翻译的 `exportThemeCss` 路线已退役——平铺进根规则会把 padding/background 变成全文属性，勿再复活该形态。
- 列表组令牌（list/li/ul/ol 前缀）的回落与链式约定：圆点形状与编号样式三级**不**链式（保持 disc→circle→square、decimal→lower-alpha→lower-roman 默认递进，回落值已进 `THEME_BASE_DEFAULTS`），圆点颜色与自定义符号/编号二三级链式回落一级（`var(--t-ul-marker-color2, var(--t-ul-marker, …))`，免登记），`li.*` 文字三项链式回落 `root.*`（规则直接命中每层 li，嵌套不叠乘）。自定义符号/编号走 `::marker content` 自绘（Chromium 能力，WebView2/浏览器可用；设了就盖过形状/样式令牌，未设回落 `normal`）：无序列表令牌存**带引号 + 尾随空格**的 CSS 字符串（`"▸ "`，引号剥离/包装在 `MarkerTextInput`，type `marker-text`）；有序列表存**编号模板编译后的 content 值**——模板 `{n}` = `counter(list-item, var(--t-ol-marker-style, decimal))`（编号样式下拉对模板同样生效），编译/反解析在 `MarkerTemplateInput`（type `marker-template`），编译器/导出/持久化对模板语法零感知。CSS 导出统一走可移植样式包（令牌走自定义属性，元素落点由 theme-base 规则天然保证）；`css-io.ts` 现在只剩导入方向——嵌套深度靠 `nestedListDepth(sel, 'ul'|'ol')` 在导入入口识别（lastSeg 归一化会丢层级）；`::marker` 伪元素规则导入时进 extraCss（视觉保留但不再令牌化）。ol 的 list-style 必须用 **longhand**（`list-style-type`）——简写会把 `list-style-position` 重置回 outside，曾因此标记位置令牌对 ol 静默失效。
- 自绘托盘菜单（`tray-menu` 窗口）的坑位：透明窗口必须在挂载时把 `html/body` 背景压成透明（`index.css` 给 body 上了 `bg-background`，不压会挡住菜单圆角外的桌面，且透明区域照样吃点击）；量菜单尺寸用 `offsetWidth/Height`（布局尺寸），不能用 `getBoundingClientRect`（弹入缩放动画期间量出来偏小）；**窗口物理尺寸 ≠ 逻辑尺寸 × 想当然的缩放**——Rust 的显示器缩放估计（`monitor_from_point` 探测链）与 WebView 实际渲染缩放（`devicePixelRatio`）在高 DPI 屏可能不一致，小了会裁掉菜单（首版实际翻过车），所以显示后必须由前端按真实 dpr 经 `resize_tray_menu` 校正；**Radix 菜单的可用高度钳制按打开瞬间的视口计算**——视口比内容矮一丝（DPI 舍入）就会触发内容自带 `overflow-y-auto` 出滚动条，且后续校正量到的是被钳过的高度，滚动条会固化（也翻过车）：对策是 Rust 开菜单前按上次尺寸**预落位**（`MENU_LAST_SIZE` 静态缓存，不显示）+ 内容加 `max-h-none!` 禁钳制，尺寸不齐宁可裁一帧等校正；菜单落位钳制显示器边界要用 max/min 链式而非 `clamp`（菜单比显示器还宽时 `clamp` 的下界大于上界会 panic）；右键开合判定在 Rust 侧用窗口 `is_visible`，菜单窗口失焦由 `window.rs` 直接 hide——两条隐藏通道（Rust 失焦 / 前端 Esc·选中项命令）最终都把窗口藏起来，前端只需保证菜单态（`open`）跟着 `tray://open` 与 `onBlur` 同步即可。托盘右键响应的是 `Down` 事件（与原生托盘菜单一致，比 Up 跟手）。菜单宽度用 `w-48!` 钉死（shadcn 内容自带的 trigger-width 变量宽度在伪触发器 1px 场景下会退化成 min-w-32）。
